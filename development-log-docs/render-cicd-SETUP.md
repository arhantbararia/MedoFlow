# Render + Cloudflare CI/CD: one-time setup

**Target layout**

| App                           | Platform                                                              | URL                                                                  |
| ----------------------------- | --------------------------------------------------------------------- | -------------------------------------------------------------------- |
| Backend (Express API, Docker) | **Render** web service `medoflow-backend` (region Ohio, next to Neon) | `https://medoflow-backend.onrender.com` (Render shows the final URL) |
| Frontend (Next.js)            | **Cloudflare Workers** `medoflow-web`                                 | https://medoflow-web.advertout-medoflow.workers.dev                  |
| Database / queue / files      | Neon Postgres · Redis Cloud · Cloudflare R2                           | unchanged                                                            |

**Pipeline** (`.github/workflows/deploy.yml`, runs in `myselfabhi/MedoFlow`)

```
PR → main ............ build gate: backend typecheck + build + Docker image, frontend OpenNext build (no deploys)
push/merge → main .... build gate ─┬─ backend changed?  → Render deploy hook (?ref=<sha>) → wait until /api/v1/health reports <sha>
                                   └─ frontend changed? → wrangler deploy to Cloudflare → smoke /, /login, /dashboard
manual run ........... Actions › "CI / Deploy" › Run workflow → deploys both apps
```

If the build fails, nothing deploys. Render auto-deploy is **off**, so only commits that passed CI reach production.

## Part A: Render (done by whoever owns the Render account)

1. **Sign in** at https://dashboard.render.com and connect GitHub. Grant the Render GitHub app access to `myselfabhi/MedoFlow`. Only the repo owner (**myselfabhi**) can approve this. Alternatively, because the repo is public, use _New › Web Service › Public Git repository_ with `https://github.com/myselfabhi/MedoFlow`.
2. **Create the service from the Blueprint:** _New › Blueprint_ → pick `myselfabhi/MedoFlow`, branch `main`. Render reads `render.yaml` and creates `medoflow-backend` (Docker, Ohio, `0.5c-512mb`, health check `/api/v1/health`, auto-deploy off).
   - Plan: the paid `0.5c-512mb` (~$7/mo) is recommended. On `free` the service sleeps after 15 min idle. That pauses the cron jobs and the AI-scribe queue worker, and the first request after sleep takes ~1 min.
3. **Fill in the prompted secrets.** Values are in the team password manager, never in git:

   | Key                                          | Value                                                                                                                                                                |
   | -------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
   | `DATABASE_URL`                               | Neon **direct** URL (host without `-pooler`): `postgresql://neondb_owner:…@ep-withered-cherry-b459hcsg.c-6.us-east-2.aws.neon.tech/medoflow-demo-db?sslmode=require` |
   | `REDIS_URL`                                  | `redis://default:…@car-copper-price-21980.db.redis.io:19914`                                                                                                         |
   | `GROQ_API_KEY`                               | voice agent (optional)                                                                                                                                               |
   | `STRIPE_SECRET_KEY`, `STRIPE_WEBHOOK_SECRET` | Stripe test keys (optional for demo)                                                                                                                                 |
   | `S3_ACCESS_KEY_ID`, `S3_SECRET_ACCESS_KEY`   | R2 API token keys for bucket `medoflow-files` (optional; without them uploads go to the container's disk)                                                            |

   `JWT_SECRET` is generated by Render. `CORS_ORIGIN`, `FRONTEND_URL` and `APP_URL` are preset to the Workers frontend URL.

4. **First deploy.** Click _Manual Deploy › Deploy latest commit_ once, then check `https://<your-service>.onrender.com/api/v1/health`, which should return `"Medoflow API is operational"`. The container runs `prisma migrate deploy` on boot; Neon is already up to date.
5. **Copy two values for GitHub:**
   - _Settings › Deploy Hook_ URL (`https://api.render.com/deploy/srv-…?key=…`). This is a secret: anyone with it can trigger deploys.
   - The service URL (e.g. `https://medoflow-backend.onrender.com`).

## Part B: GitHub (must be done by **myselfabhi**, the repo owner)

On a personal repository, only the owner can manage Actions secrets and variables. Collaborators with push access (arhantbararia) cannot.

`myselfabhi/MedoFlow` › _Settings › Secrets and variables › Actions_:

| Type     | Name                                 | Value                                                                |
| -------- | ------------------------------------ | -------------------------------------------------------------------- |
| Secret   | `RENDER_DEPLOY_HOOK_URL`             | from step A5                                                         |
| Secret   | `CLOUDFLARE_API_TOKEN`               | the `medo-worker-token` Cloudflare API token (Workers Scripts: Edit) |
| Secret   | `CLOUDFLARE_ACCOUNT_ID`              | `523c0186a1808be62e718907053c513b`                                   |
| Variable | `BACKEND_URL`                        | Render service URL from A5, no trailing slash                        |
| Variable | `FRONTEND_URL`                       | `https://medoflow-web.advertout-medoflow.workers.dev`                |
| Variable | `NEXT_PUBLIC_STRIPE_PUBLISHABLE_KEY` | optional, `pk_test_…`                                                |

CLI equivalent, run by myselfabhi:

```bash
R=myselfabhi/MedoFlow
gh secret set RENDER_DEPLOY_HOOK_URL --repo $R        # paste when prompted
gh secret set CLOUDFLARE_API_TOKEN   --repo $R        # paste when prompted
gh secret set CLOUDFLARE_ACCOUNT_ID  --repo $R --body 523c0186a1808be62e718907053c513b
gh variable set BACKEND_URL  --repo $R --body https://medoflow-backend.onrender.com
gh variable set FRONTEND_URL --repo $R --body https://medoflow-web.advertout-medoflow.workers.dev
```

Optional hardening: _Settings › Branches_ → protect `main` and require the **build** check to pass before merging. _Settings › Environments › production_ can add required reviewers before each deploy.

## Part C: first run and checks

1. Merge the PR (or click _Actions › CI / Deploy › Run workflow_ on `main`).
2. Watch: `gh run watch --repo myselfabhi/MedoFlow`. Expect `build` ✅ → `deploy-backend` ✅ ("Render is serving <sha>") and `deploy-frontend` ✅ (smoke 200s).
3. Verify:
   ```bash
   curl -s $BACKEND_URL/api/v1/health                 # commit = the merged SHA
   curl -s -o /dev/null -w '%{http_code}\n' -H "Origin: https://evil.example" -X OPTIONS $BACKEND_URL/api/v1/auth/login   # no ACAO header for bad origins
   bash frontend/scripts/cf-route-smoke.sh            # routes=68… failures=0
   ```
   Then log in at the frontend as `admin@medoflow.test` / `test1234`. The network tab should show calls to `$BACKEND_URL`.

## Rollback

- **Backend:** Render › medoflow-backend › _Events_ → pick a previous deploy → _Rollback_.
- **Frontend:** `cd frontend && npx wrangler rollback` (choose the previous version), or redeploy an older commit via _Run workflow_.

## Notes

- The Cloudflare edge Worker `medoflow-api` (PART 0) is no longer in the request path; the frontend now calls Render directly. It can be deleted with `npx wrangler delete --name medoflow-api` once Render is confirmed working.
- The PHI gate (`docs/PHI_GATE.md`) applies to Render too. Render offers a BAA only on specific plans, and Neon, Redis Cloud and Cloudflare still have no BAAs. **Synthetic data only.**
- Frontend builds must run on Linux (CI does). Windows builds skip an OpenNext patch and every page 500s.
